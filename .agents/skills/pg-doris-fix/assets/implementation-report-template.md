保存为 `fixes/<fix-batch>/implementation-report.md`。正文默认中文，目录/文件名使用英文，通用术语允许使用英文。填写实际内容，未执行不能写通过。

## 1. 本轮范围和结果

用户指定的任务、输入任务清单与归因报告位置、实际处理范围、未处理项。不自动将整张任务清单标记完成。

| 任务编号及问题 | 对应查询 | 本轮状态 | 修改及证据摘要 | 尚未解决的限制 |
| :--- | :--- | :--- | :--- | :--- |

状态使用“已修复并完成列明回归 / 已修改但回归未完成 / 不需修复（现版本已覆盖） / 当前不可实施或需补证据 / 未处理”，解释其范围。

## 2. 环境和输入身份

- SQLGlot checkout、适用仓库指令、起始 commit、原有用户修改。
- 实际测试解释器、导入的 `sqlglot.__file__`、版本、commit、本轮 diff/patch 内容指纹。commit 未变时不能省略未提交修改证据。
- Case YAML、源 SQL、`.out` 的文件指纹；数据阶段、版本、Session 和类型映射前提。
- 原始报告和归因证据位置；本轮未修改哪些原件。

## 3. 逐项修改依据

每项列：

1. 原 SQL、修复前 SQLGlot 输出/错误、实际不一致及最小复现。
2. 为什么需要改 SQLGlot；独立对照支持什么、仍不能证明什么。
3. 实际文件/函数/行号、Parser/AST/Generator 或继承能力的修改及必要性。
4. Schema/类型推断、运行时 NULL、非法输入、版本条件；默认框架调用是否真的用到修复。
5. 修改后实际生成 SQL及执行证据，不以手写候选代替。
6. 关联单元测试和回归报告中的具体查询/边界。

## 4. 代码审查与残留问题

是否有未解释回归、用户修改冲突、未运行测试或超出本轮范围的依赖；不能只修 SQLGlot 的问题给出原因和去向。说明没有通过改原 SQL/答案、数据或全局比较策略提高通过率。

## 5. 交付

代码 diff/patch、测试日志、`regression-report.md` 及证据目录的相对路径。是否 commit/push/PR 按实际写，默认均未执行。下一步由人决定，不自动派发后续任务。
