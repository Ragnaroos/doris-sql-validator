# SQLGlot 修复回归报告

保存为 `fixes/<fix-batch>/regression-report.md`。本报告必须基于修改后的 SQLGlot 新生成 SQL 的执行结果，不是仅重跑之前手写的 Doris 对照。

## 1. 对比口径

修复前后报告、输入文件及查询范围、库/数据阶段、数据库与 SQLGlot 版本、dirty patch 指纹、Session、比较规则。范围或环境不同要指出，不直接拿两个比例宣称提升。

Importer 阶段的 Parser 失败原本可能没有 Case ID：列出旧诊断的语句编号/行号和原 SQL，以及重新导入后新增的 Case ID。保存旧 YAML、不修改原脚本/`.out`；新增接受的查询单列，不能拿旧 YAML 未包含的查询冒充已回归。修复前全部导入失败时引用实际错误日志，不伪造 before 验证报告。

| 本轮相同输入查询数 | | | 列出 --id 等筛选范围 |

## 4. 针对性边界和负向输入

| 原查询/测试目的 | PG 变体 | 修改后 SQLGlot 生成的 Doris SQL/证据 | 实际执行、类型、值、顺序和错误 | 未执行或未覆盖项 |
| :--- | :--- | :--- | :--- | :--- |

边界目标 SQL 必须有修改后生成器的来源；手写 SQL 可以作独立对照，但不能替代生成器回归。NULL、空输入、重复、溢出等按相关风险选最小集合，不宣称所有输入都覆盖。

负向测试仅覆盖与本次已确认修改直接相关或用户明确要求的严格错误兼容范围。判断是否由对应输入条件触发错误，而非要求两端错误码/文本一样；其他源端负向用例默认说明、不安排逐条错误复刻，也不因未执行该专项而阻止正常输入范围的交付。已知限制仍需写清。

## 5. 验收与未解决项

逐项对照任务验收条件。信息不足或未执行单列，真实类型差异、错误原因或非确定性不能用“当前值相同”掩盖。给出可关闭的任务、只能部分交付的任务，以及新增回归/外部依赖的后续动作。
