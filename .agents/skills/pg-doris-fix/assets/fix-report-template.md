# 修复报告模板

以下是两类空白模板，不是已执行结果。报告正文中文、文件名英文；任务编号沿用归因索引。批次汇总记录共用信息，逐任务合并实施与验收，不另建执行材料目录。

## 一、批次汇总模板

保存为 `reports/fixes/<batch-id>-<fix-batch>-summary.md`。

### 1. 本轮结论与处理范围

用户明确选定的 task-id、归因汇总任务条目及首轮验证 JSON 链接；选定任务数、关联 Case 数、未选范围。按任务计数，不用 SELECT 数、候选执行次数冒充修复数。说明用户确认后的拆分/合并及原编号关系；未确认不扩大实施范围，不改写原归因文档。

| 互斥状态 | 任务数 | 含义 |
| :--- | ---: | :--- |
| 已修复并完成约定验收 | | 本次约定维度实测通过，不表示所有输入等价 |
| 已修改但未完成验收 | | 有修改，但还有失败、缺证或未执行 |
| 当前阻断 | | 尚无可验收修改，具体外部依赖/原因见任务文档 |
| 未处理 | | 选入但未开始 |
| 不需修改（当前版本已覆盖） | | 真实复测确认，无需补丁 |

五项合计等于确认后的选定任务数；未选任务不计入。一个共享修改覆盖多条 Case，仍只计一个任务。任务验收与完整 Case 匹配分开；不能把“任务通过”写成所有关联查询全部通过或 PR 已准备完毕。

### 2. 共同环境与输入

- SQLGlot checkout、适用仓库指令、起始/修复后 commit、原有用户修改、本轮相关 diff 内容指纹。
- 实际解释器、sqlglot.__file__、版本，证明验证器实际使用修改后代码。
- YAML、SQL、首轮 JSON、归因汇总及准备材料路径；配对 .out 路径/回显，不要求 .out 指纹。
- 数据阶段、双端版本/Session、比较规则和类型映射前提；改变的范围要明示。
- 共同执行命令、时间、通过/失败/跳过数；完整日志不必另存。
- 共同材料和代码依据读取后复用，按阶段批量回归；脚本提供的请求/错误/比较统计与 AI 的任务验收结论分开。同一任务多 Case、同 Case 多次候选都不重复计为修复任务，不把一次批量调用视为一个已修复问题。

### 3. 修复任务导航

| task-id 及目标 | 对应 Case ID/归因报告 | 本轮状态 | 任务报告 | 建议 PR 范围/依赖 | 修改与验收摘要 |
| :--- | :--- | :--- | :--- | :--- | :--- |

链接 `tasks/<batch-id>/<fix-batch>/<task-id>.md`；不在汇总重复全部 SQL、错误和结果表。

在同一节说明各独立 PR 范围的单一目标、相关代码/测试归属、基线与前置依赖；多个 task 经确认合并时说明不可分割性，不能只因同文件或同 Case 而合并。任务数、Case 数、建议 PR 数分别计数。这里是交付建议，不是已创建 PR 的清单，不另生成 PR 文档。

### 4. 整体回归与剩余限制

说明实际重跑的原查询、既有匹配查询、相关 dialect/core 测试和未运行范围；逐项命令及数量。不混合新增接受查询与旧覆盖的匹配率，不把负向报错算成功匹配。

列出新增回归、阻断、未满足的验收及下一步。不自动提交/推送/创建 PR；不能只改 SQLGlot 解决的原因在任务文档中展开。

## 二、逐修复任务模板

保存为 `reports/fixes/tasks/<batch-id>/<fix-batch>/<task-id>.md`。每个选定任务一份，不是每条 SELECT 一份。阻断/未处理也保留真实状态，不填假的修改或测试。

### 1. 结论与任务范围

- 任务编号、标题、互斥状态、是否满足本次验收、未满足原因。
- 原汇总 task 条目链接、已确认的纳入/排除范围、建议 PR 边界和实现依赖；多任务合并/拆分的批准范围及编号关系。
- 原归因 Case 文档和首轮查询链接；涉及 Case ID、原 SQL 位置和必要类型/阶段例外。
- 本任务验收条件与未覆盖条件；共同版本/输入链接到批次汇总，仅展开本任务差异。

### 2. 修改依据与实际实现

修复前问题、最小源 SELECT、为什么需改 SQLGlot，引用原归因的独立对照及其限制，不复制全部历史尝试。

| 实际代码/测试文件及函数 | 改动及必要性 | 影响范围/条件 |
| :--- | :--- | :--- |

保留关键 diff 或清晰规则说明；完整代码留在 SQLGlot checkout。说明继承关系、类型/Schema/版本条件、NULL 与参数边界，避免字面量特判。

说明本任务与其他任务的代码/测试归属及隔离方式，不把其他任务或原有用户改动算入本 PR。公共 helper 已存在时优先解释复用，增加基础能力时说明依赖与为什么不属于无关重构。

### 3. 修复前后实际执行

列出相关 Case 的完整源 SQL，修改前后真实生成的 Doris SQL或转译错误；已有修复前事实可直接引用原 Case。不能拿手写候选当修改后生成 SQL。

记录实际命令/API、时间、数据阶段/库、修改后 import 身份；run --stdout 的相关结果来自真正重跑，不要求保存终端 JSON。精简匹配没有生成 SQL/类型时，补取实际运行时数据，不推测被省略字段。

批量对照可将终端返回的逐请求 Markdown 事实片段整合于本节，保留各 Case/变体、完整实际生成 SQL、错误、类型和反例；不用 AI 重新抄写事实，不另存工具文件。共同规则解释一次，每条仍检查例外和独立结果；共享边界链接实际执行记录并说明适用性，不能写成所有查询都执行过该变体。事实统计不代替修复原因及验收判断。

| Case ID / stage | 执行状态/具体错误 | 字段/别名 | 类型/声明/精度 | 行数/值/重复次数 | 必要顺序/稳定性 | 完整 Case 结果 | 本任务目标观察及其他未解决问题 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

每项写一致/不同/信息不足/未执行/不适用；差异给具体反例，不复制完整大结果。不仅比较行值；实时 PG 与原 .out 不同时先解释前提，不替换基线。

一个 Case 仍有其他独立问题时，给出其 task-id 或尚未确定的事实，不改写为 MATCH，也不默认将本任务标失败。用独立最小复现及必要边界证明本任务目标；若这些验证未通过、整体差异仍可能由本任务造成或本次引入回归，则保留未验收。

### 4. 单元测试与相关边界

| 测试文件/测试名或 PG 变体 | 验证目的 | 修改后实际生成/执行结果 | 类型/值/顺序/错误观察 | 未覆盖或失败原因 |
| :--- | :--- | :--- | :--- | :--- |

| 实际命令/工作目录/解释器 | 通过/失败/跳过数量 | 具体错误与限制 |
| :--- | :--- | :--- |

边界目标 SQL须来自修改后生成器；新增导入查询保留原语句位置与新 Case ID。负向只覆盖直接相关或明确授权专项，默认源端负向不复制错误、不算成功匹配。未执行不可写通过。

### 5. 验收与下一步

逐项对照约定条件：通过证据、未通过/信息不足/未执行原因、受影响既有成功用例及新增回归。明确可关闭的范围、残留风险和不能只改 SQLGlot 解决的依赖；不宣称全输入同义。

另说明 PR 交付仍需完成的测试、上游基线复核、设计讨论和人工审查。按目标仓库贡献政策由提交者理解并审查每行修改、撰写简洁 PR 描述和披露 AI 辅助；不得将本报告状态等同于社区认可。当前授权未包含 commit/push/Issue/PR 时只给后续建议，不实际创建。

不另生成 implementation-report.md、regression-report.md、before/after/、执行 JSON、日志或 patch。仅在人明确要求 CI/统计导出时另存 JSON，并在此解释其用途；原归因报告保持不变。
