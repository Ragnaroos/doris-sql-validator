# 修复报告模板

以下是两类空白模板，不是已执行结果。正文中文、文件名英文；task-id 跨轮沿用，fix-001 表示执行轮次，不是一个任务或提交。每轮汇总记录共用信息，每轮每任务一份合并实施/验收报告，不另建执行材料目录；同轮追加尝试，不覆盖前轮报告。

## 一、批次汇总模板

保存为 `reports/fixes/<batch-id>-<fix-batch>-summary.md`。

### 1. 本轮结论与处理范围

本次模式（指定任务/整份输入持续修复）、授权输入/checkout/fork/分支、commit/push 权限、起始轮次，以及归因任务清单和首轮 JSON 链接。本轮实际纳入 task、关联 Case、未选范围及范围变更理由；指定任务模式扩大范围须获确认。保留首轮和历轮事实，当前 task 状态/关联关系可增量更新。任务数不等于 Case 数、尝试次数或 commit 数。

| 互斥状态 | 任务数 | 含义 |
| :--- | ---: | :--- |
| 已修复并完成约定验收 | | 本次约定维度实测通过，不表示所有输入等价 |
| 已修改但未完成验收 | | 有修改，但还有失败、缺证或未执行 |
| 重新打开 | | 已验收范围内发现遗漏/回归，尚未重新验收 |
| 当前阻断 | | 尚无可验收修改，具体外部依赖/原因见任务文档 |
| 未处理 | | 选入但未开始 |
| 不需修改 | | 当前版本已覆盖，或有证据更正为非 SQLGlot 问题；写明理由 |

六项表示轮次结束时的互斥状态，合计等于本轮实际纳入任务数；未纳入项不计。另列全批当前任务状态，按唯一 task-id 去重。新增、复用、重新打开、完成是本轮事件，可以重叠，不相加当任务数。一个 task 重新打开后又验收，当前只计完成，仍保留打开事件。分开说明本轮/所选任务完成和整份输入完成，不能把前者当后者或完整 Case MATCH。

### 2. 共同环境与输入

- SQLGlot checkout、适用仓库指令、起始/修复后 commit、原有用户修改、本轮相关 diff 内容指纹。
- 授权 fork 的实际 remote URL、实验分支、允许提交/推送范围；核对无夹带本地无关提交。全轮固定上游起点及累积修复链，中途换基线须显式说明并重新核验，不能混用版本结论。
- 实际解释器、sqlglot.__file__、版本，证明验证器实际使用修改后代码。
- YAML、SQL、首轮 JSON、归因汇总及准备材料路径；配对 .out 路径/回显，不要求 .out 指纹。
- 数据阶段、双端版本/Session、比较规则和类型映射前提；改变的范围要明示。
- 共同执行命令、时间、通过/失败/跳过数；完整日志不必另存。
- 共同材料和代码依据读取后复用，按阶段批量回归；脚本提供的请求/错误/比较统计与 AI 的任务验收结论分开。同一任务多 Case、同 Case 多次候选都不重复计为修复任务，不把一次批量调用视为一个已修复问题。

### 3. 修复任务导航

| task-id 及目标 | 对应 Case ID/归因报告 | 本轮状态 | 任务报告 | commit/依赖/推送状态 | 修改与验收摘要 |
| :--- | :--- | :--- | :--- | :--- | :--- |

链接 `tasks/<batch-id>/<fix-batch>/<task-id>.md`；不在汇总重复全部 SQL、错误和结果表。

说明每个 commit 的行为目标、代码/测试归属、真实 SHA/链接及前置 task/commit。一项 task 后续补遗漏可有多个 commit，多个 task 真正不可分割才共用提交；同轮、同文件或同 Case 不是合并理由。未提交、未授权推送或尚未推送如实记录；本地 commit 与远程保存分开，不用 PR 表示交付。

本地提交权限与push权限分别写明。对已授权并验收的独立修复，记录实际完整SHA、父commit、准确提交内容的测试及提交后剩余diff；不只填社区基线SHA。未实际提交时写具体阻断及是否暂停下一项，不能以“不创建PR/不push”解释持续堆积功能。旧混合改动重建时追加新提交与task的对应关系，保留原“未提交”历史，未验收的实验提交另作说明。

### 4. 整体回归与剩余限制

说明实际重跑的原查询、原匹配查询、相关 dialect/core 测试和未运行范围；逐项命令及数量。新增接受查询按源位置/出现序号对应，若生成了修复轮次 YAML 列出实际阶段路径；首轮统计不改，新旧接受范围与匹配率分开，源负向不计成功匹配。

| 新暴露问题/回归及 Case/阶段 | 实际证据与代码版本 | 复用/重新打开/新增 task 或外部去向 | 原因及下一步 |
| :--- | :--- | :--- | :--- |

同根因复用，原验收范围遗漏重新打开，独立能力新增；引入回归优先处理。不能只改 SQLGlot 解决的具体依据链接 Case/任务文档；尚不确定可修复性的事项不能直接结案。本轮发现进入归因汇总的统一任务清单，更新当前状态并追加历史，不另建台账。

### 5. 整份输入完成检查与下一轮

逐项写通过/未满足/未执行，并给真实依据：

- 原 .sql 纳入的源成功查询及所有相关 stage 均已覆盖，Parser 拒绝/导入诊断和新增接受查询无遗漏。
- 可通过 SQLGlot 安全修复的任务全部验收或已由当前版本覆盖，无未处理、未验收、重新打开、未调查或可修复性未知项。
- 固定最终 commit/代码状态下完成全阶段回归，包括原匹配与新增接受查询，无新增未解决回归；必要类型/顺序及有限边界有证据。
- 剩余不匹配逐条有不能仅靠安全 SQLGlot 修改解决的依据；环境、源证据或关键元数据阻断时不得标整份完成。源负向默认排除，不要求 100% MATCH，不宣称全输入同义。

结论填写“整份输入已完成 / 整份输入未完成”并说明原因；指定任务模式可以写“所选任务完成，但整份输入未验收”。未完成时列下一轮 task/补证范围、当前起始 commit、最近修复汇总及实际 YAML/阶段材料入口，不创建空白下一轮文件。因冲突、需扩大权限或无法取得新有效证据而暂停时，说明恢复条件，不把暂停当完成。fork 保存状态与完成结论分别记录，不以 commit/push 成功代替验收。

## 二、逐修复任务模板

保存为 `reports/fixes/tasks/<batch-id>/<fix-batch>/<task-id>.md`。本轮每个实际纳入任务一份，不是每条 SELECT 一份；跨轮同 task 仍沿用编号、链接前轮报告。阻断/未处理也保留真实状态，不填假的修改或测试。

### 1. 结论与任务范围

- 任务编号、标题、互斥状态、是否满足本次验收、未满足原因。
- 原汇总 task 条目链接、纳入/排除范围、独立 commit 边界和实现依赖；拆分/合并的理由及模式/授权范围，保留编号关系。
- 首次发现/此前处理轮次，本轮是继续、补遗漏、重新打开或新增；具体新证据和既有 task 判重依据，不只凭 SQL/错误文本相同归并。
- 原归因 Case 文档和首轮查询链接；涉及 Case ID、原 SQL 位置和必要类型/阶段例外。
- 本任务验收条件与未覆盖条件；共同版本/输入链接到批次汇总，仅展开本任务差异。
- 源语义依据、适用的类型/参数/上下文、目标能力/版本前提，以及规则为何不限于当前快照。区分“源语义转换 / 特定版本补偿，通用性待验证 / 尚无安全实现”；有限范围通过不冒充全类型域等价。
- 链接动代码前已补齐的本轮具体方案，列出独立行为、提交边界及前置commit；方案修正保留理由，不用事后结果冒充实施前判断。

### 2. 修改依据与实际实现

修复前问题、最小源 SELECT、为什么需改 SQLGlot，引用原归因的独立对照及其限制，不复制全部历史尝试。

| 实际代码/测试文件及函数 | 改动及必要性 | 影响范围/条件 |
| :--- | :--- | :--- |

保留关键 diff 或清晰规则说明；完整代码留在 SQLGlot checkout。说明继承关系、类型/Schema/版本条件、NULL 与参数边界，避免字面量特判。

说明本任务与其他任务的代码/测试归属，不夹带无关问题或用户改动。公共 helper 优先复用，新增基础能力说明依赖；提交目标只在本次授权 fork/实验分支。

| 本轮完整修复SHA/未提交阻断 | 行为变化及相关测试 | 父commit / 前置task | 本地commit状态 / push状态（已推送才附远程链接） |
| :--- | :--- | :--- | :--- |

一个 task 可以追加多个有明确目标的 commit，不按 fix 轮次打包。测试时对应的 diff/commit 与实际提交内容须一致，未验收实验提交明确授权和状态；不强推或重写已发布历史。只声明执行过的提交/推送，不伪造 SHA。

说明必要测试是在该独立commit代码上执行，还是仅在混有其他修改的工作区执行；后者不能当作准确提交内容已通过。记录提交后剩余diff的归属。获授权且已验收却未提交时，暂停下一独立修复并说明原因；明确授权的未提交试验例外如实写明。

### 3. 修复前后实际执行

列出相关 Case 的完整源 SQL，修改前后真实生成的 Doris SQL或转译错误；已有修复前事实可直接引用原 Case。不能拿手写候选当修改后生成 SQL。

记录实际命令/API、时间、数据阶段/库、修改后 import 身份；run --stdout 的相关结果来自真正重跑，不要求保存终端 JSON。精简匹配没有生成 SQL/类型时，补取实际运行时数据，不推测被省略字段。

批量对照可将终端返回的逐请求 Markdown 事实片段整合于本节，保留各 Case/变体、完整实际生成 SQL、错误、类型和反例；不用 AI 重新抄写事实，不另存工具文件。共同规则解释一次，每条仍检查例外和独立结果；共享边界链接实际执行记录并说明适用性，不能写成所有查询都执行过该变体。事实统计不代替修复原因及验收判断。

| Case ID / stage | 执行状态/具体错误 | 字段/别名 | 类型/声明/精度 | 行数/值/重复次数 | 必要顺序/稳定性 | 完整 Case 结果 | 本任务目标观察及其他未解决问题 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

每项写一致/不同/信息不足/未执行/不适用；差异给具体反例，不复制完整大结果。不仅比较行值；实时 PG 与原 .out 不同时先解释前提，不替换基线。

一个 Case 仍有其他独立问题时，给出其 task-id 或尚未确定的事实，不改写为 MATCH，也不默认将本任务标失败。用独立最小复现及必要边界证明本任务目标；若这些验证未通过、整体差异仍可能由本任务造成或本次引入回归，则保留未验收。

### 4. 单元测试与相关边界

| 测试文件/测试名或 PG 变体 | 验证目的 | 修改后实际生成/执行结果 | 类型/值/顺序/错误观察 | 未覆盖或失败原因 |
| :--- | :--- | :--- | :--- | :--- |

| 实际命令/工作目录/解释器 | 通过/失败/跳过数量 | 具体错误与限制 |
| :--- | :--- | :--- |

边界目标 SQL须来自修改后生成器；新增导入查询保留原语句位置与新 Case ID。负向只覆盖直接相关或明确授权专项，默认源端负向不复制错误、不算成功匹配。未执行不可写通过。

### 5. 验收与下一步

逐项对照约定条件：通过证据、未通过/信息不足/未执行原因、受影响既有成功用例及新增回归。明确可关闭的范围、残留风险和不能只改 SQLGlot 解决的依赖；不宣称全输入同义。

分开列出本轮新增/纠正的通用规则、既有补偿的审查结果和没有新进展的旧阻断。依源规则验证类型/转换顺序及必要组合上下文，不用边界通过数、零报错或commit数量代替语义依据；同一旧问题只有复测时明确写“仍未解决，无新增实现”。

列出后续暴露问题与 task 关系、当前统一清单状态及下一轮证据入口。当前 task 完成但整条 Case 仍失败时不扩成无关提交，继续处理关联任务；原承诺范围出现反例则重新打开。commit/push 只按明确授权，社区 Issue/PR 另行授权；fork 修复不等于社区认可。

不另生成 implementation-report.md、regression-report.md、before/after/、执行 JSON、日志或 patch。仅在人明确要求 CI/统计导出时另存 JSON。原首轮和历轮事实不改写；归因汇总的当前任务清单允许增量更新，Case 后续证据追加到同一文件。
