# 详细归因报告模板

生成 `attribution/attribution-details.md`。报告文件名使用英文，正文默认中文，通用术语可保留英文。删除模板说明，填写实际事实。

使用项目相对路径或固定提交的上游代码链接；保留真实结果与未完成范围，不加入个人会话、文件清理或补丁撤回等开发叙述。

## 1. 输入与实际完成范围

报告时间、首轮报告和交接索引、SQLGlot/数据库版本、数据阶段与外部准备证据。说明实际处理条数、未处理条数、连接/元数据/工具限制；禁止仅因读取了全部记录就写全部归因完成。

输入约定：每条 SQL 均有对应 `.out`，据其回显和出现次数读取历史成功结果或错误。转译先失败而首轮 JSON 无 source_evidence 时，仍读取原 `.out`；定位/读取失败单列工具异常，不写成用户没有结果。字段类型不足、根因未确定与源端成功/失败未知是不同问题。

先按源证据说明本轮分流：源端成功、因非法语法/参数/类型报错的负向用例、源端环境/对象前提问题、已有输出的读取异常；按此顺序明确每条的一个主要去向，数量合计输入总数。主范围为源端成功查询的转换/执行/结果差异，成功匹配可简写。例外纳入的负向专项边界单列理由，不冒充源端成功查询。

## 2. 主范围差异及专项问题

以下完整章节用于源端成功查询的差异或明确纳入的专项错误兼容问题；默认不纳入主修复的负向用例在第 3 节简写，不逐条强制改写。

### 查询编号：保持原编号

- 结论强度：已确认（注明范围）/部分确认/证据不足/未执行。
- 原因：可多项；每项用一句中文说明，不只放内部代码。
- 源文件、语句编号/行号、`.out` 对应位置与出现次数。
- 数据阶段、Session 与类型映射前提。
- 主要复现的 `.out` 成功证据；若属于负向专项，说明用户的严格兼容要求或与已确认转换修复的直接关系。

#### 源 SQL、社区输出及首轮差异

逐段给完整 SQL、实际错误/字段/结果差异；没有社区输出就给完整转译错误，不伪造 SQL。

#### 代码依据与独立 Doris 候选

给真实仓库文件、函数、行号及提交，解释依据。完整候选 SQL、是否与社区相同、执行命令和 JSON/Markdown 证据路径。未执行说明原因。

#### 已测边界与未覆盖部分

#### 原因、能否通过 SQLGlot 修复及下一步

解释哪些证据支持当前判断、还不能排除什么。若修改 SQLGlot 能解决，写所需解析/生成/类型条件；若不能安全解决或尚未证明可解，给具体 Doris 限制、框架问题或缺失实验，不只写“不支持”。关联修复任务编号。

## 3. 源端负向用例、前提问题和输出读取异常

| 查询编号与源 SQL/原件位置 | `.out` 的具体错误或读取异常 | 首轮已有目标表现 | 本轮处理及理由 | 是否有正常输入补证线索 |
| :--- | :--- | :--- | :--- | :--- |

源端负向用例写“默认不纳入主修复范围，未安排独立改写”，不是“等待完成错误复刻”。即使旧比较器 MATCH 也不计为成功匹配，不要求报错文本/错误码相同。缺表/权限等说明前提；读取器问题说明如何恢复已有输出，不推测源 SQL 的状态。

若负向例提示函数/语法能力问题，正常输入作为新变体实际执行 PG，再据其成功结果决定任务，不修改原 Case SQL 或 `.out`。所有说明留在本报告，不另增排除说明文件。
