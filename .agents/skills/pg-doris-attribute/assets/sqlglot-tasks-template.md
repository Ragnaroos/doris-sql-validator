# SQLGlot 修复任务清单

保存为 `attribution/sqlglot-tasks.md`，交给下一阶段由人显式调用的 `$pg-doris-fix`；当前归因阶段不执行修复。任务不能仅依据前五行样本、粗粒度报错相同或某个脚本分组生成。

主任务依据应是对应 `.out` 或新变体真实 PG 执行证明成功的源查询。源端因非法语法/参数/类型失败默认不安排独立改写或错误复刻任务；仅记录在详细归因的负向说明中，不列作修复积压。严格错误兼容的专项须注明用户要求或与已确认修复的直接关系和有限验收范围。已有 `.out` 读取失败先列输出读取器依赖，不以源结果未知为由推断转换缺陷。

## 2. 逐项任务

### 修复-001：用明确中文描述要解决的问题

- [ ] 尚未实施。
- 目标仓库、起始提交、建议文件/函数（实际核对后的路径，不猜结构）。
- 对应所有查询编号、源 SQL 与完整最小复现。
- 源端成功证据及 `.out` 定位；由负向线索补出的正常输入必须实际在 PG 成功，单独引用新变体证据，不借用负向 `.out`。
- 当前社区 SQL/转译错误及实际执行证据路径。
- 为什么这是 SQLGlot 需要修改的问题，而不是单纯数据缺失、目标不支持或比较器误报。
- 独立 Doris 候选、已执行的类型/行值/顺序/错误检查、边界反例及未完成项。
- 建议修改：Parser / 公共 AST / Doris Generator 的具体行为；是否依赖 Schema 或类型信息；避免把特定答案或表字段硬编码进转换规则。
- 前置依赖：需先修复的比较器、Doris 版本/能力、类型域或 Session 限制。
- 测试：SQLGlot 解析与生成单元测试；独立端到端回归；与修改直接相关的正常、NULL、空输入、重复及必要边界；结果类型和要求的顺序。负向错误检查写明与本任务的关系，不要求复刻全部源端错误或逐字保留错误码/文本。
- 验收：说明哪些差异必须消失、哪些限制仍明确保留；重跑哪些固定用例；不得改源 SQL/`.out` 或放宽全部类型来提高匹配率。
- 若独立候选在本任务纳入的验收范围内尚有未解释反例，先列“补验证/研究任务”，不得直接照抄候选提交修复；默认未纳入的负向错误复刻不是主任务的阻断项，但已观察到的限制须记录。
